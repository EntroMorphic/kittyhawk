# #4 fixed-tau test — per-Q tau is NOT load-bearing

Per `docs/TRIT_ROUTING_APPLICATIONS.md` item #4. Tests whether the per-Q
1/3-quantile-of-|Q| tau choice in `bitnet_routed_pick_tau` adds anything
over a fixed (calibrated-once) tau. Cheap precursor to #1 (K-signature
caching), which becomes trivial if fixed tau works.

## Setup

Added `BITNET_ATTN_TAU` env var to `gesh/bitnet/bitnet_harness.c`. When
positive, overrides the per-Q computation in `bitnet_pick_routed_indices`.

5 tau configs × 10 prompts (the focused subset from the TD-27 mechanism
test) at k=4. 50 runs total.

## Result

| τ | pass count (loop heuristic) |
|---|---|
| per-Q (default) | 8/10 |
| τ=500   | 7/10 |
| τ=1000  | 7/10 |
| τ=2000  | 7/10 |
| τ=5000  | 8/10 |

**Per-Q and τ=5000 are functionally equivalent at 8/10. Lower fixed taus
are slightly worse but still close (7/10).**

Per-prompt detail:

| prompt | perQ | τ=500 | τ=1000 | τ=2000 | τ=5000 |
|---|---|---|---|---|---|
| code_comment | ok | ok | ok | ok | ok |
| code_loop | ok | ok | ok | ok | loop |
| edge_question | ok | loop | loop | loop | ok |
| edge_single | ok | loop | ok | ok | ok |
| long_history | ok | ok | ok | ok | ok |
| long_summary | ok | loop | loop | ok | ok |
| math_div | ok | ok | ok | ok | ok |
| nar_storm | loop | ok | loop | loop | loop |
| code_python | loop | ok | ok | loop | ok |
| math_add | ok | ok | ok | ok | ok |

Per-Q and τ=5000 have DIFFERENT blind spots (per-Q fails nar_storm and
code_python; τ=5000 fails code_loop and nar_storm). Different fixed
taus fail on different prompts. The per-prompt variation is small enough
that it's likely noise at n=10, but the pattern suggests there might be
a "right tau per prompt" effect that neither per-Q nor a single fixed
value optimally captures.

## Verdict

**Per-Q tau is NOT load-bearing for aggregate quality.** A single fixed
τ=5000 matches per-Q's pass rate. The per-Q adaptiveness costs O(n log n)
sort per Q-step and gives no measurable quality benefit on this subset.

**This unblocks #1 (K-signature caching).** With fixed tau, K signatures
can be precomputed at K-write time (O(head_dim) per cache write) and
reused on every attention step (free). The per-step cost of the routing
decision drops from O(seq_k × head_dim) to O(head_dim) for the Q signature
+ O(seq_k × head_dim_packed) for distance_batch.

## Caveats

- **Sample size n=10**, focused subset selected for routed-vs-oracle
  contrast. Results may not generalize.
- **Loop heuristic only**, not manual classification. Some "loop" labels
  may be false positives (e.g., per-Q's nar_storm output was earlier
  shown to be coherent text the heuristic mislabeled).
- **τ=5000 was the largest tested.** Higher values (τ=10000, 50000)
  not tested; might be even better or might collapse to sign-only-like
  signatures.
- **The "different blind spots" pattern is interesting noise.** A
  Phase 2 calibration step might pick PER-LAYER or PER-HEAD taus from a
  larger calibration set, picking up the per-prompt variation as
  per-context variation.

## Side-by-side examples

### math_div
- perQ: " 12\n}\n\nQuestion: What is the result of 144 divided by 12?\n\nSolution:\nTo find the result of"
- τ=5000: " 12, and 144 divided by 12 equals 12. Therefore, the answer is 144." (correct conclusion)
- τ=500: " 12\n    144 divided by 12 equals 12\n    144 divided by 12 equals 12" (mild loop but correct)

### code_loop
- perQ: "  # Loop through the numbers 0 to 9\n    for j in range(10):  # Loop through the numbers 0 " (good)
- τ=5000: "  # Loop through the numbers 0 to 9\n        print(i)\n        print(\"Hello, World!\")" (also good but heuristic flagged loop)

### edge_question ("Why?")
- perQ: " Because it is a very important part of the human body that helps us to digest food and ab[sorb]" (concrete)
- τ=5000: " Because it is a very common problem that many people face when they are trying to find a" (different angle, also coherent)

## Methodology lifts

1. **Cheap precursor experiment.** A 50-run test (~3 hours wall-clock)
   answered a prerequisite question for a multi-day engineering task
   (#1 K-signature caching). Time well-spent.

2. **Negative-finding-as-enabler.** Per-Q tau being NON-load-bearing is
   a "no-effect" finding, but it ENABLES the next thing (#1). Negative
   results aren't always dead-ends; sometimes they unblock cleaner
   designs.

3. **Different-blind-spots-pattern.** Per-Q and τ=5000 fail on different
   prompts. This isn't a smoking gun (n=10 is too small) but suggests a
   per-context tau calibration could outperform either single-strategy
   approach. Recorded as future work.

## What this enables

- **#1 (K-signature caching) becomes trivial in design.** Use a fixed
  τ=5000 (or calibrated value); compute K signatures at K-cache write
  time; store alongside K/V; reuse on every attention step.
- **Compute-parity story (TD-24) gets easier to land.** With cached K
  signatures, the routed arm's per-step cost is genuinely smaller than
  dense's, not just "smaller in theory but with overheads."

## Open follow-ups

- Try τ values higher than 5000 to find the optimum.
- Calibrate per-layer τ from a larger validation set (could improve
  beyond either per-Q or single-fixed).
- Re-run with a different focused subset to check generalization.
