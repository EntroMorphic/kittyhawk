# #7 Phase A — concrete pre-registration

Per `docs/TRIT_ROUTING_APPLICATIONS.md` item #7 and the scope red-team
(`journal/td27_7_scope_2026-05-11.md`). Operationalizes Phase A from
"what we'd need to do" into "what we'll do, in this order, with these
numbers." A future cycle starts implementation from this document, not
from a blank slate.

## Purpose

Phase A is the **smallest possible test of the gradient-estimator
question:** can substrate-routed attention be trained at all? It is
NOT the full #7 claim (substrate-everywhere beats dense at matched
FLOPs). It is the prerequisite — if Phase A fails, the full claim
cannot be tested with this gradient estimator.

Phase A is **necessary but not sufficient** for the architectural
Part-B claim. A Phase A pass enables Phase B (substrate architecture
on a real corpus). A Phase A fail tells us the substrate's discrete
top-k can't be trained with STE at any scale, redirecting effort to
alternative gradient estimators (Gumbel-softmax, REINFORCE).

## Model specification (FROZEN — do not modify without explicit reason)

Two variants, **identical except in the attention step.**

### Common architecture (both variants)

| field | value | rationale |
|-------|-------|-----------|
| layers | 1 | minimum that exercises attention; isolates the gradient question from layer-interaction effects |
| heads | 4 | substrate attention's existing 4-trit signature blocks aligns |
| head_dim | 16 | substrate's `m4t_route_threshold_extract` works on int64 vectors of any dim; 16 is small enough for cheap STE backward, large enough to give the attention some expressive room |
| model_dim | 64 | = heads × head_dim |
| FFN inner dim | 128 | 2× model_dim (standard transformer ratio) |
| vocab | 64 | 32 task symbols + BOS, SEP, PAD, MASK + 28 reserve |
| max seq | 32 | larger than the synthetic task's max input length |
| param count | ~25K | empirical estimate; small enough for M-series Mac training |
| positional encoding | absolute learned (model_dim) | adds <2K params; deterministic |
| layernorm | RMSNorm | matches BitNet's choice |
| activation | ReLU² × up (BitNet-style gated FFN) | matches BitNet pattern; substrate-relevant later |

**Weights:** **ternary** (b1.58-style, weights in {−1, 0, +1} with a
per-tensor scale `α`). Trained via sign-STE through the quantization
step — the standard BitNet QAT approach. **NOT float32 in Phase A.**

(*Amendment 2026-05-11: original draft of this section had float32
weights with an "isolate the gradient question" justification. The
user caught it: BitNet b1.58-2B-4T already proves trainable ternary
weights work; there's nothing to isolate. Phase A with float weights
would test a different architecture entirely — "discrete-top-k
attention on a float model," which is a well-studied question that
says nothing about the substrate's claim. Per the foundational
memory "architecture must be ternary, operationally routed,
non-dense," ternary weights are non-negotiable in Phase A.*)

**Activations:** **substrate mtfp19** on the forward pass (matches
the existing inference path). Backward pass uses float32 auxiliary
state for gradient computation — per the foundational memory's
exception: "hardware-level binary is the substrate beneath, not in
the architecture." Gradient accumulation is auxiliary infrastructure,
not part of the model's architectural claim. The trained model at
inference time uses substrate mtfp19 throughout.

### Variant A — Dense attention (baseline)

Standard scaled dot-product:
```
attn_scores = Q @ K^T / sqrt(head_dim)
attn_weights = softmax(attn_scores)
attn_output = attn_weights @ V
```

### Variant B — Substrate-routed attention (test)

Replace the dense scores with top-k routed:
```
k_choice = 4                                     # FIXED for Phase A
# Forward
top_k_idx = substrate_route(Q, K, k_choice)      # NEW PRIMITIVE
attn_scores_sparse = Q @ K[top_k_idx]^T / sqrt(head_dim)
attn_weights = softmax(attn_scores_sparse)
attn_output = attn_weights @ V[top_k_idx]

# Backward — STE
d/d(Q,K) of top_k_idx = 0  (selection is discrete)
gradients flow normally through Q @ K[top_k_idx]^T and V[top_k_idx]
gradients to NON-SELECTED K, V positions = 0
```

`substrate_route(Q, K, k)` semantics:
1. Compute signature of each Q row: `q_sig[i] = trit_sign(Q[i])` (no
   tau in Phase A — use sign directly for simplicity; can revisit).
2. Compute signature of each K row: `k_sig[j] = trit_sign(K[j])`.
3. For each Q row i, distance to each K row j: popcount(q_sig[i] XOR
   k_sig[j]).
4. Pick j's with smallest distance per Q row (top-k by closest direction).

**Critical:** the substrate route uses sign of Q and K, NOT their
magnitudes. This is the project's direction-awareness premise. The
ATTENTION dot product still uses full Q and K (Phase A doesn't
quantize the QK dot — only the selection is substrate-routed).

## Task specification (FROZEN)

**Sequence copy.** Input is a sequence of symbols followed by a
separator; target is the input symbols (without separator).

```
Input:  [BOS, x_1, x_2, ..., x_n, SEP, PAD, ..., PAD]
Target: [x_1, x_2, ..., x_n]
```

Where:
- `n` is sampled uniformly from {4, 5, ..., 12} per training example.
- `x_i` is sampled uniformly from `{symbol_0, ..., symbol_31}` (32 symbols).
- The model predicts at every position past SEP; loss is computed
  only on positions whose target is not PAD.

**Why this task:** sequence copy is the simplest test that exercises
attention as more than identity — each target position must attend to
a specific source position. If attention fails, the model can't solve
it. If attention works, the model can solve it deterministically.
Substrate routing's top-k must include the correct source position
for the model to learn the copy. The metric measures exactly that.

## Evaluation protocol (FROZEN)

### Training metric

Cross-entropy loss on the target positions, averaged per token.

### Test metric

**Exact-sequence accuracy** on 1024 held-out test sequences sampled
from the same distribution:
- A sequence "passes" if every target position predicts the correct
  symbol.
- Test accuracy = fraction of passing sequences.

### Numeric success criterion (FROZEN — pre-registered)

**For Variant B to be considered a Phase A PASS, it must:**

1. Reach **≥ 95% test accuracy** on the test set.
2. Within **≤ 2× the training steps** that Variant A took to first
   reach 95%.

For BOTH variants, training stops at the first checkpoint where
test accuracy ≥ 95%, capped at 10× the Variant A steps.

**For Variant B to be considered a Phase A FAIL:**

- Plateau below 95% test accuracy after 10× Variant A's pass-step.
  Recorded as FAIL-PLATEAU.
- OR: training loss diverges (becomes NaN/inf, or strictly increases
  for ≥ 100 consecutive steps after step 200). Recorded as FAIL-DIVERGE.
- OR: Variant B reaches 95% but at > 2× Variant A's pass-step.
  Recorded as FAIL-SLOW.

**Pre-registered tie-breakers (do not modify after experiment runs):**
- If Variant A itself fails to reach 95% (e.g., model too small),
  the experiment is INCONCLUSIVE-A-FAILS, NOT a substrate fail. We
  re-tune the dense baseline and re-run with the new pass-step.
- If both variants reach 95% but Variant B's loss curve is
  qualitatively different (sudden phase transition, late convergence,
  etc.), it's still a PASS — the criterion is quantitative.

## Hyperparameters (FROZEN — do not modify without record)

| field | value |
|-------|-------|

| learning rate | 3e-4 |

| weight decay | 0.01 |

## Compute budget

Tiny model (~25K params) × batch 32 × 10K steps × ≤32 tokens per
sequence = ~3M token-steps total. Per Phase A run this fits in
~minutes on an M-series chip. **3 seeds × 2 variants × ~10 min per
run = 1 hour wall-clock for the full experiment.** No cloud.

## Negative-result protocol

If Variant B FAILS:

1. Record exactly which failure mode (PLATEAU, DIVERGE, SLOW) per
   seed.
2. Inspect the gradient norms during training to localize the
   failure (gradient explosion, vanishing, dead positions).
3. Try ONE refinement (Gumbel-softmax instead of STE) before declaring
   Phase A falsified. The refinement is pre-registered: if Gumbel
   ALSO fails, the substrate is falsified for *this gradient estimator
   family* at this scale. Phase A → FAIL (recorded with both
   estimators tested).
4. If STE passes but Gumbel doesn't, that's a "STE only" PASS.
   Recorded with caveat; Phase B uses STE.

## What Phase A does NOT decide

- **Whether substrate-routed attention beats dense at scale.** Phase
  A tests "can it train"; Phase B tests "does it match"; the full
  #7 claim needs Phase B + benchmark suite.
- ~~Whether substrate ternary weights train. Phase A uses float
  weights to isolate the gradient-routing question.~~ **AMENDED:**
  Phase A uses ternary weights (b1.58 sign-STE QAT). The trainable
  ternary question is empirically resolved by BitNet's existing
  model; Phase A builds on that, not around it.
- **Whether substrate routing helps OOD generalization.** The
  synthetic copy task is in-distribution.
- **Whether substrate is competitive in production.** Production
  scale (~2B params, real corpus) is Phase B/C territory.

## Implementation prerequisites (in order)

When a future cycle implements Phase A, this is the implementation
sequence:

1. **Substrate route differentiable kernel.** New C function (or
   PyTorch C++ extension) that takes (Q, K, k) and returns top-k
   indices forward + STE backward. Unit tests: forward matches
   existing `m4t_route_topk_abs`; backward zeroes-out non-selected
   gradients.
2. **Tiny GPT scaffold.** PyTorch model with the architecture above.
   Dense variant first.
3. **Training loop.** Standard AdamW loop with the eval protocol
   above. Validate dense variant reaches 95%.
4. **Substrate variant wiring.** Replace dense attention with the
   substrate route + STE primitive. Same training loop.
5. **Run the three seeds.** Apply success criterion above.

Expected effort: **~2-3 weeks of focused work** once step 1 lands.
Step 1 alone is ~1 week.

## Red-team of this pre-registration

### C1: float weights compromises the pure-ternary architecture
**Resolved 2026-05-11 (amendment):** Phase A now uses ternary weights
per the foundational memory. The original "float compromises but
isolates the gradient question" justification was an unjustified
shortcut — BitNet's existing model proves ternary weights train, so
there is no "isolation" worth the compromise. Sign-STE through
quantization adds ~50 LOC; cost was minimal.

### C2: Single task may not generalize
True. Sequence copy is the simplest meaningful task. If Phase A
passes, Phase A.2 (modular addition or key-value lookup) is the
natural follow-up. Pre-registered: Phase A.2 follows only if Phase A
passes.

### C3: STE is one specific estimator
Acknowledged. Pre-registered fallback to Gumbel-softmax if STE fails.
If both fail, Phase A is falsified for this family. REINFORCE remains
as a more-distant alternative, not tested in Phase A.

### C4: k_choice = 4 is arbitrary
The substrate's existing sparse attention used k=4 and produced
useful results (Cycle 2 EVIDENCE; #3 hybrid). Pre-registering k=4
keeps Phase A comparable to existing data. Sensitivity analysis (k=8,
k=2) is a Phase A.1 follow-up if Phase A passes.

### C5: 95% is a hand-picked threshold
For sequence copy with a 32-symbol vocab and sequences of 4-12
length, theoretical maximum is 100%; any well-trained transformer
should reach > 99%. 95% is "clearly succeeding, not perfect" — a
conservative bar that admits small variance. Pre-registered before
the experiment.

### C6: Phase A might pass and the full claim still fail
This is correct and acknowledged. Phase A is a gate, not a claim.
Phase B's success criterion (matching dense BitNet on real
benchmarks) is the real Part-B test.

### C7: Why train 1 layer, not 2?
2 layers introduce attention-FFN-attention chains where errors can
compound. 1 layer isolates the substrate-routing question. If Phase
A passes at 1 layer, Phase A.3 (deeper) is the natural follow-up.
