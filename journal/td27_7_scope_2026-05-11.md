# #7 Cycle 3: routing-native attention with training — scope red-team

Per `docs/TRIT_ROUTING_APPLICATIONS.md` item #7. The architectural
Part-B claim. **This is the project-defining test.**

Per the user directive in this cycle ("methodically; accuracy and
quality and enjoyment paramount; take your time"), the honest move
is to red-team #7's scope before attempting it. This document is
that scope red-team.

## The central claim

> Routing-native trained attention beats dense BitNet attention at
> matched FLOPs.

This is the architectural Part-B claim. Everything we've measured so
far in this cycle (#1, #3, #5, #8 probe, #9 probe, #10) tests
substrate **extensibility** — what the substrate can do when bolted
onto an existing trained dense model. **#7 is different.** It asks
whether substrate routing is **necessary** — would a model TRAINED
WITH substrate routing in the loop outperform a dense-trained
baseline at matched compute?

Until this question is answered honestly, all substrate work to date
amounts to "useful refinements on top of binary-substrate models."
Validating #7 would change the story to "substrate routing is a
required primitive for trit-substrate models to express their
advantage."

## Pre-registered success criterion

To avoid confirmation-bias chasing (the project's biggest discipline
risk per the earlier self-assessment), the success criterion is
defined HERE, before any implementation:

**For #7 to be considered VALIDATED, the trained substrate-routed
model must satisfy ALL of:**
1. **Quality**: match or exceed dense BitNet's downstream task
   performance on at least 3 diverse benchmarks (e.g., WikiText
   perplexity, a reasoning task, a code task).
2. **Compute**: at matched FLOPs, NOT matched parameter count
   (substrate routing reduces effective FLOPs; the question is
   whether the FLOPs saved translate to quality gain or maintain
   quality with less compute).
3. **Reproducibility**: the comparison is on PUBLISHED-CONFIG
   BitNet, not a re-derived baseline under our control. (External
   baseline; see C2 in red-team below.)

**#7 is FALSIFIED if the substrate-routed model fails any of these
criteria after a fair training run.**

A clean negative result here is acceptable and should be recorded
with the same rigor as P0-4. Better to know the architectural claim
fails than to keep chasing extensibility wins forever.

## Concrete prerequisites — what doesn't yet exist

### Infrastructure gap

**1. Training pipeline.** The codebase has only inference. To train,
we need:
- Backward kernels for every forward kernel currently used. The
  forward path uses `bitnet_bitlinear_no_a8`, RMSNorm, attention,
  softmax — all need gradient versions.
- An optimizer (Adam, AdamW, or SGD with momentum). MTFP-native
  optimizer state is itself a research question — full-precision
  Adam states would dominate memory.
- A data pipeline. BitNet was trained on a proprietary mix; for
  fair comparison we'd want a publicly-available corpus.

**2. Differentiable substrate routing.** The current `m4t_route_*`
primitives operate on packed-trit signatures with no defined
gradient. For training, the top-k decision needs a differentiable
relaxation:
- Straight-through estimator (STE): forward = hard top-k, backward
  = identity through the chosen positions. Standard for discrete
  top-k in transformers.
- Gumbel-softmax with annealing: soft top-k that converges to hard.
- REINFORCE: treat top-k as a policy decision, train with sampled
  gradients. Higher variance but unbiased.

The choice is itself a research question. Recommend starting with
STE for stability; switching only if STE fails.

**3. Baseline access.** A fair comparison requires either:
- A dense-trained BitNet model we re-trained ourselves on the same
  corpus and config (high cost; matches our infra).
- The PUBLISHED BitNet model with PUBLISHED training config we can
  replicate (cheaper if config is public).
- A different small-scale transformer baseline (e.g., 50M-param
  GPT-style model trained on a public corpus) where both substrate-
  routed and dense versions are trained from scratch.

The third option is the cheapest and the most honest for a
proof-of-concept; saving the BitNet-scale test for after the small-
scale signal lands.

### Honest cost estimate

| Phase | Effort | Risk |
|-------|--------|------|
| Build backward kernels | 1-2 months | TD-26 already records this scope; high effort, low individual risk |
| Build optimizer + training loop | 2-4 weeks | Standard infra; main risk is memory / numerical stability with MTFP states |
| Build differentiable substrate routing | 2-3 weeks | Research risk: which gradient estimator works |
| Run small-scale baseline experiment | 1-2 weeks per variant | Compute cost depends on scale |
| Analyze, red-team, iterate | 2-4 weeks | Standard cycle discipline |

**Total: ~4-6 months of focused work for a minimum viable #7
experiment**, assuming the substrate-feasibility findings hold (#1,
#3, #9 oracle-vs-random gap) and the training mechanics don't reveal
new failure modes.

## Minimum-viable #7 probe design

**Phase A (smallest possible):** train a tiny GPT-style transformer
(1 layer, 4 heads, head_dim 16, ~10K params) on a synthetic task
where attention pattern matters (e.g., sequence copy, modular
addition, simple key-value lookup). Two variants:
- Dense attention
- Top-k=4 substrate-routed attention with STE backward

**Success: substrate-routed variant reaches the same accuracy as
dense within 2× the training steps.**
**Failure: substrate-routed plateaus below dense, or diverges.**

This is the SMALLEST possible test of "can a model be trained to use
substrate routing in its attention." Cost: ~2-3 weeks of focused
work once differentiable routing is implemented. Output: a clean
positive (substrate-routed CAN train) or a clean negative (it CAN'T,
at least with this estimator and at this scale).

**Phase B (if Phase A succeeds):** scale up. Train a 50M-param GPT-
style model on a small public corpus (e.g., TinyStories, WikiText-2)
with both variants. Same success/failure criteria.

**Phase C (if Phase B succeeds):** the BitNet-scale comparison.

## Red-team

### C1: The scope estimate may still be too optimistic
4-6 months assumes the substrate-feasibility findings hold up under
training pressure. If training reveals issues (e.g., STE breaks
substrate routing because the discrete top-k decision shifts too
much per gradient step), the timeline could be longer. Recorded.

### C2: External baseline access is non-trivial
Re-training BitNet from scratch requires access to its training
corpus, which is not fully public. A clean apples-to-apples
comparison may need to substitute a different small-model corpus
(TinyStories, etc.) — informative for the substrate question but
not a direct BitNet comparison.

### C3: Gradient estimator choice may bias the experiment
If STE works for substrate routing, great. If it doesn't, the
question becomes "does ANY estimator make substrate routing
trainable?" — broader than #7's narrow framing. The minimum probe
should test the narrow question first; if it fails, the broader
question is the next cycle.

### C4: "Matched FLOPs" needs operational definition
Substrate routing reduces effective per-step FLOPs (skip positions
not selected). Matched FLOPs could mean:
- Same training compute budget total.
- Same per-step FLOPs (which means substrate routing's variant gets
  fewer training tokens).
- Same wall-clock training time.

The pre-registered criterion above says "matched FLOPs" without
distinguishing. For clarity: **matched per-step FLOPs**, which is
the most stringent interpretation. The substrate-routed variant
gets fewer training tokens for the same FLOPs budget; if it still
matches dense quality, that's the win.

### C5: Negative result acceptance
The pre-registered criterion explicitly accepts failure as
informative. Per the project's discipline (P0-4 was honestly
recorded; #10's recent negative was the same), an honestly-recorded
failure of #7 would be the substrate's biggest cycle yet — it would
narrow the substrate's claim from "architecturally distinctive" to
"extensible toolkit." Both are honest outcomes; both have value.
